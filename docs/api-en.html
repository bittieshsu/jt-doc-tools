API manual

Jason Tools Document Toolbox exposes a RESTful API. Every tool has an endpoint, ready to plug into automation, your own systems or scheduled jobs.

Basic principle: the API is open by default (matching the web UI); to lock it, an administrator turns on enforce mode on the admin “API Token” page and issues bearer tokens.

1. Authentication

Authentication disabled (default)

A new install has authentication off, so every /api/* Ready to use, no token needed.

1. Authentication

Enabling API tokens

An administrator goes to admin → API Tokendownload)

  1. Click “issue a new token” → enter a purpose (for example gitlab-ci) → you receive a 64-character hex token (shown only once, so store it safelysettings (site-wide, with no per-person exceptions).
  2. Tick “Enforce — refuse anything without a token” and save

After that, every /api/* must carry one of the following:

Authorization: Bearer 64char-hex-token-here

or as a query string:

GET /api/jobs/abc123?token=64char-hex-token-here

Missing or invalid token → 401 Unauthorized :

{"ok": false, "detail": "需要有效的 API token（Authorization: Bearer ...）"}

Tokens are managed from admin / jtdt Managed from the CLI, entirely separate from web authentication (jtdt-admin / LDAP / AD).

12. Integration examples

Shell: watch for a job to finish and download it

#!/bin/bash
TOKEN="YOUR_TOKEN"
API="http://localhost:8765"

JOB=$(curl -fsSL -X POST "$API/api/llm-review" \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@filled.pdf" -F "template_id=vendor_form_v3" \
  | jq -r .job_id)

echo "Job: $JOB"

while :; do
  S=$(curl -fsSL "$API/api/jobs/$JOB" -H "Authorization: Bearer $TOKEN")
  STATE=$(echo "$S" | jq -r .status)
  PROG=$(echo "$S" | jq -r .progress)
  echo "  $STATE  $PROG"
  [ "$STATE" = "completed" ] && break
  [ "$STATE" = "failed" ] && { echo "Failed"; exit 1; }
  sleep 2
done

curl -fsSL "$API/api/jobs/$JOB/download" \
  -H "Authorization: Bearer $TOKEN" \
  --output reviewed.pdf
echo "Saved: reviewed.pdf"

14. Rate limits and upload size

CurrentlyThere is no built-in rate limit. When deploying, add one at the reverse proxy (nginx / Caddy):

  • client_max_body_size 100Mto fetch the result (a single PDF, or a ZIP for several files)
  • proxy_read_timeout 900s + proxy_send_timeout 900s) returns
  • proxy_buffering off(required, otherwise large PDFs are rejected)
  • With nested nginx layers (a self-hosted LLM proxy plus jt-doc-tools, two nginx hops) every layer needs— one layer left at the default breaks the whole chain
  • If it must be publicly exposed, also add limit_req_zone (required — a single LLM inference often takes 5–15 minutes, and the 60s default is a guaranteed 504)

See OPS.md 's “reverse proxy” section and the “504 Gateway Timeout” troubleshooting flow.
