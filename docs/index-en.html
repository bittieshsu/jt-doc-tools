Why self-host?

Send a PDF to an online tool and the data has already left.

There are plenty of “free” PDF, image and Office tools online: form filling, stamping, merging, compression, signing, encryption…
Two clicks and it's done — butyour file has been uploaded to someone else's server. Contracts, HR records, finances, customer data, ID numbers, bank accounts — are you comfortable with that?

What worries people about online PDF tools
  • Files go to a third-party server andyou cannot confirm when they are really deleted
  • Most of them are closed source, soyou don't know what the server does with your data
  • Free tiers often come with terms aboutchanges to the privacy policy, training AI on your files terms
  • Uploading ID numbers, bank accounts, customer lists and contracts means personal-data and GDPR exposure
  • Your network audit never sees it and your SIEM never receives it, socompliance cannot be traced
  • Cross-border or cross-site transfers raise data residency questions
Self-hosted and open source is the only way to be sure
  • Files never leave your server — no third-party API, no telemetry
  • Open source (AGPL-3.0) — audit anything you like
  • Audit records live in your own SQLite, and can be forwarded to an internal SIEM in real time (syslog / CEF / GELF)
  • Roles and a permission matrix: your organisation decides who may use which tool
  • Personal-data and GDPR compliance: the data stays in your own server room or network
  • One-line install, running on the Linux, macOS or Windows machines you already have — no licence fees

Keep any PDF or PNG a tool produces on the server in one click, visible only to your account; pull it back into any tool's upload area without hunting for the file or uploading it again. Administrators can turn the feature on or off and set quotas and retention centrally.

Save to workspace

Load from workspace

Administrator control

The whole feature can beturned on or off(disabled means completely hidden), with a central setting foreach person's quota, per-file limits and retention hours, and the ability to clear a user's usage. With authentication off it becomes one shared workspace.

New in v1.14

Background jobs and completion notices: submit and close the tab

Slow work — conversion, OCR, sentence translation — runs on the server, so you don't have to watch a progress bar. You are told when it finishes, and the result is kept in “My workspace”. Administrators see the whole queue and resource usage, and can adjust every concurrency limit.

26 tools run as background jobs

PDF to Word or slides, OCR, sentence translation, compression, merging, watermarks, stamping…you can close the tab right after submitting. “My jobs” shows progress, queue position and elapsed time, and a running job can be cancelled. Tools whose result is not a single file (sentence translation, for example) willtake you back to the original pagewhen you return.

You are told when it is done

In-app notifications show an unread count;Email emails carry the site logo and the tool's icon. Eight more channels are available — Telegram / Slack / Teams / Discord / LINE / Webhook and others (currently markedin development, not yet verified against the real services). Messages contain only the tool name, file name and status —never file contents.

Web responses always come first

Conversion processes run at a lower priority and arelimited to a subset of cores(one core is kept for the web interface by default), so the interface stays responsive while a large file converts — the conversion itself is simply a little slower. Memory is estimated before dispatch and, if there is not enough, the jobwaits in the queuerather than being forced through and taking the machine down; job state lives in the database, so nothing disappears when the service restarts.

Priority dispatch

An administrator can nominatea small number ofusers — senior staff, or genuinely time-critical work — and their jobsgo straight to the front of the queue, to be dispatched next.Running jobs are never interrupted(killing a conversion halfway only leaves a broken file); the effect is “you are next”, not “you go now”. People on the list still queue among themselves in order, and a job still waits if memory is short.

Administrators see everything

A site-wide job list:who submitted it, which tool, which file, queue position and how long it has run, filterable to running jobs only, and every one can becancelled directly. Before maintenance you canpause dispatch, letting current jobs finish without starting new ones (a running conversion is a separate child process and cannot be frozen — the interface says so plainly rather than pretending the button stops it).

Performance is visible and the limits are adjustable

Running and queued counts, Office conversion usage, CPU and memory are all on one page, andone click shows the historical trend; memory is measured from theactual child processes(soffice is what really uses it). All five concurrency limits are adjustable, andhowever large you set them, actual free memory still caps them.

New in v1.14

AD / LDAP: a directory integration that holds up, and that you can manage

Connecting is only the start. What actually goes wrong is this: the primary DC restarts, permissions hang off a primary group and never take effect, leavers stay in the system, accounts get reused by someone else. This round covers all of it.

Failover across several domain controllers

The server field acceptsseveral hosts(comma or newline separated), tried in order — when the primary DC is restarting, sign-in moves to the next one instead of locking the whole company out. Connections and queries both time out, so when a DC is unreachable you geta clear message within secondsrather than waiting until you assume the system is down. A DC that comes back is returned to the rotation automatically.

AD primary groups count too

In AD, theprimary group (primaryGroupID) does not appear in memberOf — the classic AD integration trap: a company makes a department the primary group, hangs permissions on it, and not one member gets them, while the user's “Member Of” tab givesno hint at all why. Primary groups are now folded into permission resolution automatically. OpenLDAP has no such concept, so nothing changes there.

Leavers and disabled accounts are visible

Directory sync used to beadd-only: once AD disabled or deleted someone, their account, role assignments and group memberships all stayed here, and “who is still in this system?” had no answer. The user list now has“gone from the directory”and“disabled in AD”views and badges. The judgement isbased only on a full scan — a name-filtered sync sees just part of the directory, and using it as the baseline would mark the whole organisation as leavers.

Bulk disable, with a safety valve

“Gone from the directory” can be hundreds of people across a dozen pages — one clickdisables them all, and before it runs you are toldhow many people would actually change. It can also disable themautomatically after each sync ((off by default). The safety valve is the important part: if a single run would touch more than 20% of the directory accounts, itstops entirely and changes nothing — an expired service-account password or a changed search base both look like “the whole company disappeared”, and doing nothing is the right answer then. It alsoonly disables, never deletes: the account and its permissions are kept, so one click restores someone who comes back.

Who is signed in right now

The user list shows thenumber of people online(one person with three browsers counts once), and every account shows its currentdevices — browser and operating system, source address, last activity — and they can besigned out individually or all at once, with the action recorded in the audit log. If an account may have leaked, you can kick every device without changing the password first.

Assign permissions before they ever sign in

Click any user in the directory browser toassign roles directly, without waiting for a first sign-in — a new joiner can work on day one. Each row under “member of” can be given group permissions on the spot too. Previously you could only assign to a whole OU, but “only these two people in this OU are finance” is the far more common need.

See at a glance what someone can actually use

Permission sources are spread across four places (directly assigned roles, groups includingnested parent groups, OUs, and direct tool grants), which is hard to explain when something goes wrong. While editing a user you can expand theeffective permissionspanel: which tools this person ends up with, andwhich rule granted each one. Read it straight out for an audit response or a handover.

See an expiring password before it bites

For the user, an expired password looks likesuddenly cannot sign in, and only then do they ask an administrator. The list now marksdays until expiry(already expired is marked separately), so you can warn people. The date isthe value AD computes itself, so people under a fine-grained password policy (PSO) or with “password never expires” are correct — deriving it from the domain default would be wrong.

AI extras (optional)

12 tools support LLM assistance for another step up in speed and quality

Point it at your own LLM (local Ollama / vLLM / LM Studio / DGX Spark all work) and the smart options light up in these 12 tools.The core tools do not depend on an LLM at all, and work 100% without one.

text

Sentence translation

Sentences are sent to the LLM, source and translation side by side, each re-translatable on its own. A Taiwanese IT terminology list is built in, and an optional “document domain” hint (legal / medical / technical) sharpens the vocabulary.

Effect: long contracts and papers translate far faster in parallel than by hand

text

Document translation (whole office documents)

Translate a whole Word, Excel or PowerPoint file into another language,producing the same format and layout — only the text changes; rules, tables, headers, footers and images all stay where they were. Paragraphs are sent to the LLM, and the first six pages come back as a side-by-side preview.

Effect: a whole contract or policy comes back translated, with no re-layout needed

text

Extract text (paragraph re-flow)

After PyMuPDF extracts the text, each block goes to the LLM to rejoin sentences that line breaks had split. Exports TXT / Markdown / DOCX / ODT.

Effect: body text chopped up by the PDF layout reads smoothly again

vision

Auto-fill forms (verification)

After filling, the LLM reviews the rendered result (PNG) field by field, spotting misplaced or truncated values and wrongly ticked checkboxes.

Effect: on a 30-field vendor form, check only the fields the LLM flags instead of every one

text

Document redaction (extra detection)

Regex catches fixed formats (ID numbers, phone numbers, bank accounts, tax IDs); the LLM adds context-sensitive cases such as “customer code A-2024-0815” or “Manager Wang”.

Effect: non-standard formats and context-dependent fields that regex misses are caught by the LLM

text

Text redaction (extra detection)

The same, but for plain text — support conversations, logs, email bodies. Paste it in or upload .txt / .md.

Effect: the same regex + LLM double detection, for plain-text situations

text

Word count (summary / keywords)

After counting, the LLM can add a summary and a list of key concepts (optional, off by default).

Effect: faced with an unfamiliar long document, read the summary first and decide whether to read on

text

Annotation report (automatic grouping)

Every annotation in the PDF is pulled out and the LLM groups them by theme (text to change, formatting issues, open questions, already agreed … it decides freely).

Effect: on a long document reviewed by several people, similar suggestions gather in one place

text

Document compare (summary of changes)

After the line-by-line diff, the LLM adds three to five sentences explaining what changed overall (optional, off by default).

Effect: after a contract, draft or spec is revised, read the summary before deciding whether to go clause by clause

text

OCR (typo correction)

After EasyOCR or Tesseract runs, the LLM uses the surrounding context to fix common OCR mistakes. A hallucination guard is built in: corrections apply only when the word count is identical before and after, so the LLM cannot rewrite freely.

Effect: cleaner OCR output, ready for search and editing

text + vision

Pre-submission check (meaning + visual)

After the structural checks (page size, embedded fonts), the LLM checks the content for meaning (are required fields really filled, is the wording self-consistent) and a vision model inspects the PNG (does a stamp cover text, is the layout broken).

Effect: catches the “literally right but wrong in meaning” and “looks wrong” cases that regex and structural checks miss

text

e-Invoice processing (accounting category)

After scanning, invoices are sent to the LLM in batches — by seller tax ID, company name and industry — to decide the accounting category (fuel, meals, postage …). Rules run first and the LLM fills the gaps; your own rules can override both.

Effect: categorised automatically before the expense claim, with no manual picking

Enterprise administration

More than a toolbox — a platform you can control

With authentication on, the management capabilities an organisation needs are all there (all open source, with no paid tier).

A

Multiple authentication realms

Supports both local accounts / LDAP / Active Directory. The same username can exist in several realms (jason@local + jason@ldap), and the source is chosen from a dropdown at sign-in. The LDAP settings page has “test server connection” and “test account sign-in” buttons to verify the configuration in one click.

B

Single sign-on

OIDC + SAML, ready for Microsoft 365 / Entra ID, Google Workspace, Keycloak, Okta, Authentik and others. It works alongsidelocal, LDAP and AD sign-in (keeping a local break-glass account); accounts are created on first sign-in, IdP groups map to roles, and single logout (SLO) is supported.

C

Reverse Proxy SSO

Kerberos / SPNEGO: a user already joined to the AD domain and signed in to Windows issigned in automaticallyafter the front-end Nginx verifies them, with no username or password; machines outside the domain still get the sign-in page. It reuses the existing LDAP / AD lookups, roles, audit and 2FA, and guards against spoofing with “trusted reverse-proxy IP plus header override”. See reverse_proxy_sso.md.

D

Roles and permissions

Seven built-in roles:administrator, auditor, general user, records, finance, sales, legal and security. You can add your own roles and grant tool permissions to users, groups or OUs. An in-memory cache keeps permission lookups off the critical path.

E

Audit log

Sign-in, sign-out, lockout, permission changes, setting changes and tool calls including the uploaded file name are all recorded. Writes go to SQLite (WAL) asynchronously so the service is unaffected. Filter and export to CSV; kept 90 days by default, then cleaned automatically.

F

Log forwarding

Three formats are supported:syslog (RFC 5424 UDP/TCP), CEF (ArcSight), GELF (Graylog). Several destinations run in parallel; after three failed retries the event is downgraded to a local audit record. Ready for Splunk / Graylog / ArcSight and other SIEMs.

G

Upload log

A separate “upload log” page lists every file uploaded through a tool — who, when, which tool, what filename, how large, and the HTTP status. Fully traceable.

H

File retention and cleanup

Separate retention settings for form-filling, stamping and watermark history, temporary uploads, job results and audit records, with scheduled cleanup (at startup and every 6 hours). “Keep forever” (-1) is available.

I

Settings backup and import

All admin settings (authentication, roles and permissions, notifications, concurrency, retention, company details, synonyms …) can beexported as a single zip, ready to import when moving machines or rebuilding after an incident. You can also scheduleregular backups(daily or weekly) to a directory, with old files rotated automatically.

Why two accounts

Compliance frameworks require separation betweenwhoever runs the systemandwhoever reads the records — an administrator should not be able to peek at the files users actually uploaded, and an auditor should not change system settings. Neither side has full access: that is separation of duties.

Enforced TOTP 2FA

On first sign-in, the auditor role is taken to /2fa-verify automatic setup (a QR code is shown) → scan it with Google Authenticator, Microsoft Authenticator, Authy or 1Password → enter the 6-digit code. An auditor cannot turn their own 2FA off

Several auditors

Beyond the built-in jtdt-auditor, an administrator can use sudo jtdt audit-user create <name> to add as many auditors as needed (useful in larger companies where IT, legal and internal audit review separately). Each auditor has their own 2FA.

Auditor actions are recorded too

every auditor view writes a record auditor_view audit event (path / method / IP), so an administrator can see what an auditor looked at, while the auditor cannot delete it (there is no delete endpoint in the UI — the role is read-only by design).

2FA is available to everyone

Not just auditors — any user (including LDAP / AD accounts) can turn on TOTP 2FA themselves from the “My account” dialog, and turn it off again later (except the auditor role).

Emergency recovery from the CLI

An administrator can recover offline:jtdt auth show / disable / set-local, jtdt reset-password <user>, jtdt audit-user create. Even a forgotten password or a mis-configured LDAP needs no reinstall and loses no data.

Deployment

One-line install on all three platforms

Administrator rights are required. The installer detects and installs OxOffice or LibreOffice, downloads a self-contained Python, registers a system service and starts it at boot.

Single-machine mode (personal)
Ready to use straight after installing — authentication is off by default, so anyone can open a browser at 127.0.0.1:8765 work equally well. Ideal for a one-person desktop workflow.
Server mode (team / organisation)
Deploy to a Linux server and turn onlocal accounts / LDAP / ADin “authentication settings”, together with roles and the permission matrix, audit and log forwarding. Shared across the internal network, and controllable.

$f="$env:TEMP\jtdt-install.ps1"; try { Invoke-WebRequest 'https://cdn.jsdelivr.net/gh/jasoncheng7115/jt-doc-tools@main/install.ps1' -OutFile $f -UseBasicParsing -TimeoutSec 15 -ErrorAction Stop; powershell -NoProfile -ExecutionPolicy Bypass -File $f } catch { Write-Host "[X] 下載安裝腳本失敗：$($_.Exception.Message)" -ForegroundColor Red; Write-Host "請檢查網路（VPN？防火牆？DNS？）後重試。" -ForegroundColor Yellow }; Read-Host '按 Enter 關閉'

When it finishes, open a browser at http://127.0.0.1:8765/ and you are ready.
